# SensorReport — ver 0.0.0

GOTのNG判定数と工場の対象NG本数（屑＋保留）を製番ごとに照合し、棒グラフで比較します。

[GitHub Pagesで開く](https://tohokusteel.github.io/SensorReport/)

ローカルで使う場合は、`index.html` をWindowsのEdgeまたはChromeで開いてください。インストール、サーバー、Pythonは不要です。3ファイル（index.html / core.js / app.js）を同じフォルダに置きます。

GOTのCSVを選び、CM1KuzuHoryuBoardから工場実績を貼り付けます。工場実績はCSV・TSV・TXTファイルからも読み込めます。貼り付けとファイル入力には列名が必要です。UTF-8とShift_JISを読み込めます。Excelブック自体は未対応です。

製番を文字列として前後空白だけ除去し照合します。GOTは `:DEV_COMMENT` の列名を使い、`NG判定数` を採用します。工場の対象NG本数は、屑1・屑2・保留1・保留2のうち、対象の屑コードに該当する本数の合計です。屑計は二重加算しません。

初期対象はヘゲ線・陥没・その他CM（名前で判定。101/102のコード単独にも対応）。寸大・寸小・曲りは除外します。未知の屑コードは未分類です。その他CMのコードだけが入力された場合は、画面で確認して対象に変更してください。データ内の屑コードをチェックボックスで表示します（0件の「000」は省略）。既知の対象屑コードは初期チェックあり、未知の屑コードは未チェック・要確認です。初期チェックの正式な対象は今後確定します。空欄の本数・負数・非整数・列数不一致・空製番は不正行になります。

同じ製番の複数行は自動合算せず重複扱いにします。片側だけの製番は未照合で、欠けた値を0にしません。未分類がある工場値は既知対象だけの暫定値です。差分は比較可の行のみです。日付での自動照合やタイムゾーン変換は行いません。

再読込は各側のデータを置換します。失敗した場合は前回値を保持しメッセージを表示します。屑コードの設定は画面を閉じるまで保持します。データ・設定の永続保存、複数ファイルの履歴統合、自動取込、結果出力は今後の拡張です。

GitHub Pagesではアプリのファイルを取得するために通信します。読み込んだ実績データと集計結果はブラウザ内で処理し、外部に送信しません。工場データは `data/`、出力は `output/` に保管しGitに追加しないでください。既存のカメラ・Hailo・GPIOコードは読み込みません。ラズパイへの配備対象外です。

テスト: アプリのフォルダで `node --test tests/*.test.js`。架空データだけを使います。

グラフは工場の対象NG本数の降順で、未確定値は末尾です。行間スライダーとグラフ下端のドラッグで表示密度・高さを調整できます。明細表は初期状態で折りたたみ、列見出しをクリックすると昇順・降順を切り替えます。表のソートはグラフの順序に影響しません。
